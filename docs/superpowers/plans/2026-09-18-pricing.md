# Pricing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar listas de precios normalizadas, precios por producto, asignación opcional a clientes y resolución determinística con fallback `GENERAL`.

**Architecture:** Pricing tendrá commands y queries separados. Los commands usarán `JdbcTemplate`, transacciones cortas, autorización `ADMIN_ALL` y `AuditService`; las queries devolverán `PageResponse` y un resolvedor explícito para pedidos futuros. La migración V5 creará el modelo, migrará el precio actual de cada producto a las tres listas iniciales y agregará la relación opcional en clientes.

**Tech Stack:** Spring Boot 3.5.16, Java 21, Spring JDBC, Spring Security method security, PostgreSQL 16, Flyway, JUnit 5, Mockito, Docker Compose.

## Global Constraints

- Tres listas iniciales: `GENERAL`, `LISTA_2` y `LISTA_3`.
- El máximo es de diez listas totales, incluyendo activas e inactivas.
- Los precios usan `NUMERIC(19,4)` y no pueden ser negativos.
- Solo `ADMIN_ALL` puede crear, modificar o desactivar listas y precios.
- Una lista desactivada no puede asignarse a clientes ni seleccionarse explícitamente para pedidos nuevos.
- No se eliminan físicamente listas ni precios.
- La lista default debe ser `GENERAL` en esta fase.
- Un precio ausente no hace fallback a otra lista; la resolución devuelve `404`.
- Si el cliente no tiene lista asignada, la resolución usa `GENERAL`.
- Los cambios de precio tienen efecto inmediato.
- No se implementan todavía snapshots de pedidos, descuentos ni vigencias futuras.

**Interfaces:**
- Consumes: `JdbcTemplate`, `AuditService`, authenticated `ADMIN_ALL` authority.
- Produces:
  - `UUID createList(String code, String name)`
  - `void renameList(UUID listId, String name)`
  - `void setListStatus(UUID listId, String status)`
  - `void setProductPrice(UUID listId, UUID productId, BigDecimal price)`
  - `POST /api/pricing/lists` with `201 {"id":"..."}`
  - `PUT /api/pricing/lists/{id}` with `204`
  - `PATCH /api/pricing/lists/{id}/status` with `204`
  - `PUT /api/pricing/lists/{listId}/products/{productId}` with `204`

- [ ] **Step 1: Write failing command tests**

Cover these cases:

```java
createList("CUSTOM", "Clientes")       // creates when total < 10
createList("CUSTOM", "Clientes")       // rejects duplicate code
createList("L11", "Once")               // rejects when total == 10
setListStatus(generalId, "INACTIVE")     // rejects default GENERAL
setListStatus(inactiveId, "ACTIVE")      // activates
setProductPrice(listId, productId, new BigDecimal("10.2500")) // upsert
setProductPrice(listId, productId, new BigDecimal("-1"))      // rejects
```

Verify every successful mutation calls `AuditService.record` with the operation names `PRICELIST_CREATE`, `PRICELIST_UPDATE`, `PRICELIST_STATUS`, or `PRODUCT_PRICE_UPDATE`.

- [ ] **Step 2: Implement transactional commands**

Use parameterized SQL and `@Transactional`. Enforce the list count with `select count(*) from catalog.price_lists`, validate code/name/status/price before SQL, reject inactive lists for price changes, and use PostgreSQL upsert:

```sql
insert into catalog.product_prices(price_list_id, product_id, price, created_at, updated_at)
values (?, ?, ?, ?, ?)
on conflict (price_list_id, product_id)
do update set price = excluded.price, updated_at = excluded.updated_at
```

Reject deactivation of the default list and reject prices for missing/inactive products. Use `EmptyResultDataAccessException` for missing IDs and `IllegalStateException` for business conflicts.

- [ ] **Step 3: Implement admin-only controller DTOs**

Use explicit records with validation:

```java
record CreateListRequest(@NotBlank @Size(max = 40) String code,
                         @NotBlank @Size(max = 120) String name) {}
record RenameListRequest(@NotBlank @Size(max = 120) String name) {}
record StatusRequest(@NotBlank String status) {}
record ProductPriceRequest(@NotNull @DecimalMin("0.0000") BigDecimal price) {}
```

Annotate all four mutating controller methods with `@PreAuthorize("hasAuthority('ADMIN_ALL')")` and return the exact status codes from the spec.
